# Обслуживание и восстановление

## Перед изменениями

Сохраните вывод `rustdeskctl client` в личном месте, а серверную копию делайте через `rustdeskctl backup`. Публичный ключ можно передавать своим клиентам; файл `id_ed25519` и архив `.private.tar.gz` публиковать нельзя.

Действия ниже выполняются в root-shell Entware. Не используйте `killall nginx`, общую очистку iptables или восстановление полной чужой таблицы firewall для обслуживания этого пакета.

## Восстановление ключа и базы после чистой установки

Архив созданного этим проектом backup содержит пути `opt/etc/rustdesk`, `opt/var/lib/rustdesk` и служебные файлы. Сначала просмотрите список:

```sh
tar -tzf /opt/var/backups/rustdesk-entware/backup-ВАША-ДАТА.private.tar.gz
```

Используйте только собственную доверенную копию. Не распаковывайте неизвестный архив от root поверх `/`.

1. Установите Entware и этот пакет на совместимом ARM64-устройстве. Убедитесь, что `/opt` находится на постоянном накопителе.
2. Выполните `rustdeskctl stop`, затем `rustdeskctl backup`, чтобы сохранить новую идентичность перед заменой.
3. Распакуйте старый архив **в отдельный пустой каталог на накопителе**. Для восстановления идентичности нужны `opt/var/lib/rustdesk/id_ed25519`, `id_ed25519.pub` и база SQLite вместе с сопутствующими файлами из этой согласованной копии.
4. Проверьте, что `rustdeskctl status` показывает остановку. Перенесите старый каталог данных на место `/opt/var/lib/rustdesk` целиком, предварительно сохранив текущий под другим именем. Не смешивайте новые и старые файлы базы.
5. Посмотрите числовой `uid` в **новом** `/opt/etc/rustdesk/server.json`. Назначьте владельцем восстановленного каталога данных этот UID и такой же GID, каталогам права `700`, файлам ключей и базы — `600`. Не используйте UID из старой копии вслепую: на другом роутере он может быть занят.
6. Не восстанавливайте старый конфиг поверх новой сети без проверки: адрес, VPN-интерфейсы и подсети могут отличаться. Задайте их через `rustdeskctl configure` либо сохраните корректные параметры новой установки.
7. Запустите `rustdeskctl start`, затем `rustdeskctl client`. Публичный Key должен совпасть со старым. Проверьте реальный сеанс с двумя клиентами.

Установщик не делает такое восстановление автоматически: выбор чужой базы или неправильного UID может лишить доступа. Если нужна только смена адреса, используйте `configure` — перенос базы не нужен.

## Изменение сети

`rustdeskctl configure` сохраняет резервную копию и ключи. Например, разрешить ZeroTier и отдельный VPN-пул:

```sh
rustdeskctl configure --address 192.168.50.1 --interfaces 'zt0 ppp+' --networks '10.147.17.0/24 10.77.0.0/24'
```

Ограничения применяются как **интерфейс И подсеть источника**. При нескольких интерфейсах каждый разрешает каждую перечисленную подсеть. Для более сложных индивидуальных ACL нужна отдельная проверенная доработка firewall; редактор произвольных правил в этой версии не предусмотрен.

После изменения адреса не забудьте поменять поля ID/relay у клиентов. Отдельной автоматической миграции всех клиентов нет.

## Диагностика

| Симптом | Что проверить |
|---|---|
| «Другая установка RustDesk» | Существующие файлы/службы; установщик специально не перезаписывает их и их ключи |
| «Только ARM64» | `uname -m`; этот архив нельзя запускать на MIPS/ARMv7 |
| Ошибка TLS/скачивания | Время, DNS, сертификаты, доступ к GitHub, свободное место; не отключайте проверку TLS |
| SHA-256 не совпал | Прекратить установку; сравнить релиз и источник, не запускать изменённый архив |
| Supervisor есть, hbbs/hbbr нет | `rustdeskctl logs`; готовность firewall, netfilter-модулей и ожидаемого правила XKeen |
| Клиент «не готов» | VPN и маршрут до адреса ID, TCP/UDP 21116, серверный Key, выключенный WebSocket |
| ID виден, соединения нет | Доступ обеих сторон к объявленному relay:21117, пароль/подтверждение удалённого клиента |
| После переподключения VPN пропал доступ | Изменилось имя интерфейса или пул источников; проверить `ip -o -4 addr show` и счётчики RDE_INPUT |
| Низкая скорость | Путь ZeroTier/VPN, облако KeenDNS для SSTP/OpenConnect, CPU/USB роутера, принудительный relay |

Сервисные команды:

```sh
rustdeskctl status
rustdeskctl logs
iptables -S RDE_INPUT
iptables -t mangle -S RDE_OUTPUT
iptables -t nat -S RDE_NAT
ip rule show
ip route show table main
```

`RDE_INPUT` должен разрешать localhost, выбранные интерфейсы/подсети и завершаться `DROP`. На IPv6 разрешён только localhost. Собственные цепочки проверяются и восстанавливаются supervisor; ручное изменение этих цепочек не является постоянной настройкой.

### Проверка длительного соединения

Обычный открытый TCP-сокет без обмена данными не равнозначен сеансу клиента RustDesk. В официальном `hbbr` 1.1.16 relay закрывается после более чем 30 секунд отсутствия входящих данных; см. [реализацию тайм-аута](https://github.com/rustdesk/rustdesk-server/blob/1.1.16/src/relay_server.rs#L513-L516). На проверенном роутере полностью молчащая тестовая пара закрылась примерно через 33 секунды. Для проверки устойчивого транспорта нужен периодический обмен, а затем отдельная проверка простоя настоящих GUI-клиентов. Установщик не изменяет этот тайм-аут и не патчит официальный сервер.

Пакеты с UID RustDesk получают исключение из OUTPUT mangle/nat; в режиме `xkeen` IPv4 также получает DSCP 62 и существующую метку `0xffffa00`. Если в вашей версии XKeen изменился смысл этих меток, не переносите этот режим автоматически — проверьте фактический путь.

## Что остаётся после удаления

`rustdeskctl uninstall --yes` останавливает только записанные процессы с ожидаемыми путями, создаёт закрытый архив, удаляет бинарники, автозапуск, hook, рабочие каталоги и собственные правила. Пакеты Python/curl не удаляются: они могут использоваться другими программами Entware. Резервные копии и пустые lock-файлы могут остаться; они не запускают службы.

При ошибке остановки или очистки установщик/удаление прекращают работу и сохраняют материал для диагностики. Не продолжайте удалять файлы работающего сервера вручную, пока не проверили PID и состояние правил.
