# Обновление, откат и защита от повторных падений

## Переход с KeenDesk 0.1.0

Старая версия не знает команду `update`. Для первого перехода в SSH Entware выполните:

```sh
(set -eu; rd_setup="$(mktemp /tmp/keendesk-update.XXXXXX)"; trap 'rm -f "$rd_setup"' EXIT; curl -fsSL --proto '=https' --tlsv1.2 https://raw.githubusercontent.com/Zhanchuraev/KeenDesk/v0.2.2/install.sh -o "$rd_setup"; /bin/sh "$rd_setup" --upgrade)
```

Для новой установки используется обычная команда из README, без `--upgrade`. Повторный запуск без этого флага ничего не обновляет: показывает действующие настройки. Чужая установка без маркера KeenDesk автоматически не мигрируется.

## Следующие обновления

```sh
rustdeskctl update
# Либо конкретный стабильный тег:
rustdeskctl update --version v0.2.2
```

Команда получает последний стабильный GitHub Release. Расписание обновлений не создаётся. Если выбранная версия уже установлена или старее текущей, изменений не будет. Если GitHub API ограничил запросы, укажите конкретный опубликованный тег.

Обновление KeenDesk не означает установку самой новой версии RustDesk Server: версия `hbbs`/`hbbr` закреплена в каждом релизе KeenDesk. В 0.2.2 это по-прежнему OSS 1.1.16.

## Что делает обновление

1. Загружает файлы релиза, проверяет полный список и SHA-256. Проверяет официальный архив сервера, архитектуру ELF и запуск `--version` до остановки действующих служб.
2. Проверяет свободное место: минимум 256 МиБ. Большая база и предыдущие копии требуют дополнительного места. Не удаляет старые копии автоматически.
3. Останавливает сервер и панель, сохраняет согласованный снимок старого кода, бинарников, конфигурации и каталога данных. Ключи и настройки остаются прежними.
4. Ставит загрузочный обработчик восстановления и записывает журнал незавершённого обновления. Затем заменяет файлы, применяет собственные правила firewall и запускает службы.
5. Дважды проверяет ID по TCP, ответ по UDP и реальную двустороннюю передачу через relay. Сверяет ключи и конфигурацию с исходными. Только после успешных проверок помечает обновление завершённым.
6. При ошибке автоматически возвращает предыдущую версию и данные. Если процесс обновления оборван, следующий запуск `/opt/etc/init.d/S90rustdesk start` или загрузка роутера восстановит незавершённую транзакцию.

SHA-256 подтверждает целостность относительно загруженного манифеста. Манифест и код получаются по проверяемому HTTPS из этого GitHub-репозитория; отдельной независимой цифровой подписи релизов пока нет. Установщик не отключает TLS-проверки.

Снимки находятся в `/opt/var/lib/keendesk-update/snapshot-*`. Они содержат **приватный ключ и базу**, доступны root и не зашифрованы. Не публикуйте их. Не удаляйте снимок, на который ссылается `pending.json` или `last-update.json`. Удаление KeenDesk оставляет резервные копии и снимки для восстановления.

Защита от прерывания проверяется остановкой процесса обновления в CI. Это не аппаратное испытание внезапного отключения питания накопителя. Повреждение USB/файловой системы может потребовать восстановления из отдельной копии.

## Ручной откат

```sh
rustdeskctl rollback --yes
```

Возвращает предыдущую версию **вместе с настройками и базой на момент обновления**. Добавленные после обновления регистрации исчезнут из рабочей базы; текущая база и настройки предварительно сохраняются отдельной командой backup. Ключ сервера должен совпадать со снимком — иначе автоматический откат запрещён. После отката на 0.1.0 новые команды и панель недоступны; повторный переход выполняется командой с `--upgrade` выше. Загрузочный обработчик восстановления остаётся совместимым с обеими версиями.

При обычной ошибке откат выполняется сразу. При повреждённом снимке автоматическое восстановление останавливается до изменения файлов; сохраните журнал и действующие копии для диагностики. Не удаляйте `pending.json`, чтобы скрыть ошибку.

## Защита от бесконечных перезапусков

Supervisor считает неожиданные завершения и ошибки запуска `hbbs`/`hbbr` вместе. После первых четырёх событий задержки составляют 5, 10, 20 и 40 секунд. **Пятое падение за 10 минут блокирует оба процесса.** Блокировка записана на накопителе и сохраняется при перезапуске supervisor и роутера. После 10 минут непрерывной работы обоих процессов счётчик очищается.

```sh
rustdeskctl doctor
rustdeskctl logs
# После устранения причины:
rustdeskctl restart
```

Явные `start` и `restart` снимают блокировку. Автозапуск Entware её не снимает. Обычная остановка, backup, пересоздание firewall Keenetic и ожидание готовности XKeen не считаются падениями. При ошибке firewall серверы остаются остановлены, пока правила не восстановятся. Защита относится к падениям процессов; это не автоматическая диагностика всех возможных зависаний протокола.
