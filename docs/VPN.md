# Доступ к RustDesk без публичного IPv4

Адрес в полях RustDesk должен вести на сервер **по работающему сетевому маршруту**. Имя KeenDNS само по себе не превращает обычные порты RustDesk в HTTPS. Здесь используются обычные клиенты RustDesk с выключенным WebSocket.

## ZeroTier

ZeroTier создаёт отдельную виртуальную сеть и **не использует KeenDNS**.

1. Создайте свою сеть ZeroTier и подключите к ней роутер и клиентские устройства. Разрешите нужных участников в управлении сетью.
2. Назначьте роутеру стабильный IPv4 в сети ZeroTier. Проверяйте отсутствие пересечения с локальными подсетями.
3. В Entware найдите Linux-интерфейс и адрес:

   ```sh
   ip -o -4 addr show
   ```

4. При единственном IPv4 на `zt…` установщик сам выберет этот интерфейс и адрес. Иначе используйте `RD_ADDRESS` и `RD_INTERFACES`.
5. Укажите выданные установщиком ID/relay/Key на обоих клиентах. ZeroTier должен оставаться подключённым либо до сервера должен существовать маршрут через другой узел ZeroTier.

Пример изменения уже установленного сервера:

```sh
rustdeskctl configure --address 10.147.17.1 --interfaces 'zt0' --networks '10.147.17.0/24'
```

Это пример, а не адрес, который существует в вашей сети. На некоторых устройствах интерфейс имеет длинное имя `zt…`, а не `zt0`.

Состояние `ONLINE` ZeroTier и успешный ping полезны для диагностики, но не заменяют проверку TCP/UDP RustDesk и сеанса. Маршруты и правила самого ZeroTier также должны пропускать нужный трафик.

## SSTP через KeenDNS

Встроенный SSTP-сервер Keenetic поддерживает подключение через облако KeenDNS при частных адресах с обеих сторон. В Windows есть встроенный SSTP-клиент; другим платформам может понадобиться приложение. См. [инструкцию производителя](https://support.keenetic.ua/titan/kn-1811/en/19090-sstp-vpn-server.html).

В веб-интерфейсе установите компонент SSTP, зарегистрируйте KeenDNS с действительным сертификатом, включите SSTP-сервер, задайте пул VPN-адресов и пользователей. Используйте **адрес сервера, который показывает панель SSTP**, с нужным портом по инструкции производителя. Сначала добейтесь обычного VPN-подключения и доступа к роутеру.

Далее настройте RustDesk на внутренний IPv4 роутера, достижимый через SSTP. Это может быть LAN-адрес роутера, если он маршрутизируется в туннель. В `RD_INTERFACES` указываются входящие Linux-интерфейсы VPN, а в `RD_NETWORKS` — пул **адресов VPN-клиентов**.

Условный пример после проверки фактических интерфейсов:

```sh
rustdeskctl configure --address 192.168.50.1 --interfaces 'ppp+' --networks '10.77.0.0/24'
```

`ppp+` здесь только пример шаблона: не считайте его универсальным именем SSTP. Подключите тестового пользователя, сравните `ip -o link show` и `ip -o -4 addr show` до/после подключения. При сомнении используйте точное имя интерфейса и проверьте поведение после переподключения VPN.

## OpenConnect через KeenDNS

Встроенный сервер OpenConnect появился в KeeneticOS 4.2.1. Он поддерживает облачный доступ при частном IP, используя HTTPS-транспорт; адрес подключения генерируется в панели сервера. Нужен совместимый VPN-клиент. См. [официальную инструкцию OpenConnect](https://support.keenetic.com/hero/kn-1011/en/38655-openconnect-vpn-server.html).

Установите компонент, включите сервер, настройте пользователей и адресный пул, скопируйте показанный адрес сервера. Проверьте VPN и маршрут до внутреннего адреса роутера. Затем укажите этот **внутренний IP** в полях ID/relay RustDesk, а фактические Linux-интерфейсы OpenConnect и пул его клиентов — в настройках доступа установщика.

Не подставляйте домен внешнего OpenConnect-сервера вместо IP RustDesk: домен используется для подключения **VPN-клиента**, а приватный IP — для RustDesk **внутри уже подключённого VPN**.

Названия Linux-интерфейсов зависят от реализации/прошивки. Их нужно проверить на своём устройстве, а не предполагать `tun0`. Шаблон `tun+` допустим только с конкретным адресным пулом; точные имена предпочтительны, когда они стабильны.

## Маршруты, firewall и проверка

Для SSTP/OpenConnect удобно отделять два этапа:

1. **VPN работает:** соединение установлено, с клиентского устройства достижим внутренний адрес роутера. Если VPN подключился, но маршрута нет, сначала исправьте маршруты VPN/разрешения пользователя.
2. **RustDesk доступен:** разрешённый входящий интерфейс и подсеть совпадают с тем, что реально видит Linux на роутере. На обоих клиентах задан одинаковый достижимый адрес сервера и его публичный ключ.

Узнать конфигурацию и счётчики:

```sh
ip -o -4 addr show
ip route show table main
iptables -nvL RDE_INPUT
rustdeskctl status
rustdeskctl client
```

Проверка TCP с Windows, после подключения VPN:

```powershell
Test-NetConnection 192.168.50.1 -Port 21116
Test-NetConnection 192.168.50.1 -Port 21117
```

Этот тест не проверяет UDP, регистрацию и реальный рабочий стол. После него подключитесь в RustDesk по ID удалённого клиента, проверьте файл, простой и повторное подключение. Если нужен доступ только через relay, включите соответствующую настройку клиента.

Оба клиента не обязаны иметь прямой маршрут друг к другу для работы через relay, но **каждый обязан достигать ID-сервера и relay**. Для прямого соединения между клиентами потребуются соответствующие маршруты и разрешения VPN.

Не обязательно направлять весь Интернет клиентов через роутер. Для этой задачи достаточно маршрута к адресу RustDesk-сервера. У SSTP/OpenConnect поверх облака скорость зависит от облачного транспорта; перетаскивать через него весь Интернет обычно не нужно. Наличие NAT для выхода VPN-клиентов в Интернет и доступ к сервису на самом роутере — разные настройки.

## Если есть публичный IPv4

Можно использовать обычные TCP/UDP RustDesk без VPN. Укажите свой внешний IPv4 или DNS-имя, разрешите **точный WAN-интерфейс**, при необходимости ограничьте источники. KeenDNS в таком сценарии должен разрешаться прямо на ваш публичный адрес; режим «Через облако» обычные порты RustDesk не публикует.

Пример параметров для явно выбранного публичного режима:

```sh
RD_ADDRESS=rustdesk.example.net RD_INTERFACES=eth3 /bin/sh /tmp/rustdesk-entware-install.sh
```

`rustdesk.example.net` и `eth3` заменяются фактическими значениями. Этот пример открывает native-порты RustDesk источникам с WAN-интерфейса; используйте его только когда именно это требуется. На самом роутере это правила INPUT. Если публичный IP находится на вышестоящем вашем маршрутизаторе, на нём отдельно понадобится корректный проброс TCP 21115–21117 и UDP 21116.

## Что эта инструкция не делает

Она не создаёт и не оплачивает сети/аккаунты, не включает SSTP/OpenConnect на вашем роутере автоматически и не изменяет его KeenDNS. Варианты VPN описывают способ доставки обычного RustDesk-трафика. Отдельный эксперимент с WSS-публикацией RustDesk не является частью этого проекта.
